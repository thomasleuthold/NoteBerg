# NoteBerg Nextcloud App — Implementation Plan

## Overview

Port NoteBerg to a Nextcloud app while maintaining a **single codebase** for both the Tauri desktop app and the Nextcloud app. The two targets share all frontend code under `src/`; platform differences are handled via a `VITE_PLATFORM` build flag.

### Key simplifications vs. the Tauri app

- **No authentication** — the user is already logged in to Nextcloud; `@nextcloud/axios` handles session headers automatically
- **No encryption** — data lives on Nextcloud's server; Nextcloud manages access control; always off in NC build
- **No sync engine** — reads and writes go directly to WebDAV; no local IndexedDB cache, no conflict resolution, no etag tracking
- **Tombstones kept** — still required to signal deletions to Tauri fat clients that share the same NoteBerg folder
- **No settings panel** — theme from Nextcloud, language from Nextcloud (`OC.getLocale()`), no credentials, no sync config, no master password; settings UI hidden entirely in NC build

## Step 3 — Vite Build Config ✅ DONE

**Goal:** Replace the stub script with a real Vite build that outputs into `js/` and adds a `VITE_PLATFORM=nextcloud` define. The PHP boilerplate files move from the stub script into permanent files in the repo.

### 3.1 Promote PHP files from generated → permanent

Move the PHP files out of `scripts/build-nextcloud-stub.js` and commit them directly to the repo:
- `appinfo/info.xml`
- `appinfo/routes.php`
- `lib/Controller/PageController.php`
- `templates/index.php`
- `img/app.svg`

The `build:nextcloud` script then becomes a pure Vite build, not a file generator.

### 3.2 `vite.config.js` changes

```js
const platform = process.env.VITE_PLATFORM || 'tauri';

export default defineConfig({
  define: {
    'import.meta.env.VITE_APP_VERSION': JSON.stringify(getAppVersion()),
    'import.meta.env.VITE_PLATFORM': JSON.stringify(platform),
  },
  build: {
    target: 'esnext',
    outDir: 'dist',
    rollupOptions: platform === 'nextcloud' ? {
      output: {
        entryFileNames: 'js/noteberg-main.js',
        chunkFileNames: 'js/[name].js',
        assetFileNames: (info) =>
          info.name?.endsWith('.css') ? 'css/noteberg-styles.css' : 'assets/[name][extname]',
      },
    } : {},
    minify: !process.env.TAURI_DEBUG ? 'esbuild' : false,
    sourcemap: !!process.env.TAURI_DEBUG,
  },
});
```

### 3.3 `package.json` scripts

```json
"dev:nextcloud": "VITE_PLATFORM=nextcloud vite build --watch",
"build:nextcloud": "VITE_PLATFORM=nextcloud vite build"
```

`dev:nextcloud` runs Vite in watch mode — rebuilds `js/` on every save, browser refresh picks it up immediately.

### 3.4 Update `templates/index.php`

\OCP\Util::addStyle('noteberg', 'css/noteberg-styles');
?>

## Step 5 — Rewrite `storage.js` for Nextcloud (WebDAV)

**Goal:** Replace IndexedDB reads/writes with direct WebDAV calls. This is the core of the migration. The exported API surface stays identical so all callers above `storage.js` are unchanged.

### Data layout on WebDAV

The Nextcloud app writes to the same folder structure the Tauri app uses, ensuring full interoperability:

```
NoteBerg/
├── index.json              ← lightweight index: all note + notebook metadata
├── notes/
│   └── {id}.json          ← full note (strokes, content, media positions)
├── notebooks/
│   └── {id}.json
├── media/
│   └── {id}.{ext}         ← binary media files
└── tombstones/
    └── {id}.tomb          ← deletion markers for fat client compatibility
```

### The index file pattern

`index.json` contains all metadata needed for the overview (title, notebook, modified, thumbnail). The overview loads this single file — avoiding N GET requests on startup. Opening a note fetches the individual `notes/{id}.json`.

### Implementation approach

Use separate implementation files, selected at build time:

```
src/modules/storage.js              ← exports only; delegates to platform impl
src/modules/storage.indexeddb.js   ← Tauri implementation (current code)
src/modules/storage.webdav.js      ← Nextcloud implementation (new)
```

### API surface (unchanged)

```js
export async function getAllNotes()        // reads index.json
export async function getNote(id)         // GET notes/{id}.json
export async function saveNote(note)      // PUT notes/{id}.json + patch index.json
export async function deleteNote(id)      // DELETE notes/{id}.json + write tombstone
export async function getAllNotebooks()   // reads index.json
export async function saveNotebook(nb)   // PUT notebooks/{id}.json + patch index.json
export async function deleteNotebook(id) // DELETE + tombstone
export async function saveMedia(...)     // PUT media/{id}.ext
export async function getMedia(id)       // GET media/{id}.ext
// etc.
```

### Save debouncing

During drawing, strokes are saved continuously. Debounce WebDAV PUTs to **2–3 seconds** to avoid flooding the server. The canvas buffers strokes in memory between saves.

### Using `@nextcloud/axios`

```js
import axios from '@nextcloud/axios';
import { getCurrentUser } from '@nextcloud/auth';

const BASE = `/remote.php/dav/files/${getCurrentUser().uid}/NoteBerg`;

async function getNote(id) {
  const res = await axios.get(`${BASE}/notes/${id}.json`);
  return res.data;
}

async function saveNote(note) {
  await axios.put(`${BASE}/notes/${note.id}.json`, note);
  await patchIndex(note);
}
```

## Step 6 — Wire Up Overview, Note Open/Save/Delete, Media, Tombstones

**Goal:** End-to-end functionality working against WebDAV.

Order of implementation:

1. **Overview** — load `index.json`, render note cards and notebooks
2. **Note open** — GET `notes/{id}.json`, render canvas + text
3. **Note save** — PUT `notes/{id}.json` + patch `index.json` (with debounce)
4. **Note delete** — DELETE + write tombstone to `tombstones/{id}.tomb`
5. **Media** — GET/PUT `media/{id}.ext`
6. **Notebooks** — CRUD on `notebooks/{id}.json` + index
7. **Smoke test** — create a note in NC app, verify it appears in Tauri app and vice versa

## Open Questions / Decisions Deferred

1. **Handwriting recognition** — the Windows.UI backend (`localhost:5000`) doesn't translate to Nextcloud. Options for a future version:
   - Disable in NC build (v1 approach)
   - Integrate a cloud OCR API (MyScript, Azure Ink Recognizer, etc.)
   - Allow users to configure a custom recognition endpoint

2. **Offline support** — explicitly out of scope for v1.

3. **Card size setting** — deferred to v2; use a fixed default in v1.

4. **Nextcloud App Store publishing** — deferred; requires AGPL license review and app store automated checks.

5. **`@nextcloud/vite-config`** — evaluate whether to adopt the official shared Vite config or keep the current custom one. The official config adds Nextcloud conventions but may conflict with the Tauri build.
